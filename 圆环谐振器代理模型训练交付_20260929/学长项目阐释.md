# 学长圆环项目阐释

这份文档只解释仓库里的 `圆环谐振器代理模型训练交付_20260929`。数字和流程以该目录里的代码、配置、训练日志和 CSV 为准。两个 COMSOL 模型文件不在 git 里，在 Release `models-20260929`。

这是学长已经做完的仿真和模型。下面的品质因数、频率和误差是他的结果，引用可以，不能写成你们这次的实测。

## 它在回答什么

给定一枚硅圆环的半径、平均环宽，以及环宽沿圆周的起伏，预测两件事：

- 呼吸模态的品质因数 Q
- 这个模态的频率，单位 MHz

温度不在输入里，也不在输出里。表里没有频率随温度变化。它回答不了「拐点在多少度、加热要多少功率」。

## 圆环怎么写进表里

每一行是一枚圆环的一种形状。

- `a_ring_um`：平均半径，微米。七个 CSV 合在一起，范围大约 122 到 130。
- `h_ring_um`：平均环宽，微米。范围大约 8 到 13.5。
- `C1_um` 到 `C8_um`，`S1_um` 到 `S8_um`：环宽沿圆周的起伏。把圆周角记成 θ，第 k 阶贡献是 `Ck·cos(kθ) + Sk·sin(kθ)`，单位都是微米。

文件名里的 width2、width4、width6、width8 是这批数据最高写到第几阶，不是环宽等于 2、4、6、8 微米。width2 的表只存到 `S2`，更高阶在读入时补 0。width6 存到第 6 阶，第 7、8 阶补 0。width8 存到第 8 阶。

环宽沿圆周不能太窄，也不能太宽。`feature_engineering.py` 和 `project_config.json` 里的限制是最窄 6.5 μm、最宽 13.5 μm。程序在 360 或 720 个角度上把宽度加出来，检查最小和最大。

由这些系数再算出一组派生量，给网络用，不需要人另填：

- 各阶幅度 `ampk = sqrt(Ck² + Sk²)`
- 宽度的最小、最大、标准差、相对起伏
- 宽度离 6.5 和 13.5 还有多少余量
- 宽度沿圆周变化有多急（一阶、二阶导数的均方根）
- 低阶、中阶、高阶起伏各占多少
- 二阶、四阶、八阶对称还差多少，以及是否接近镜面对称
- 半径除以平均环宽

`03_最终模型/metadata.json` 里列出的输入一共 59 列：18 列原始几何，其余是上面这些派生量。

## 一次仿真在做什么

真仿真不在这台 Linux 虚拟机上跑。`config/project_config.json` 写的是 Windows 上的 COMSOL 6.3：

- `comsolbatch.exe` 和 `comsolcompile.exe` 的路径是 `D:\comsol\COMSOL63\Multiphysics\bin\win64\`
- 研究标签 `std3`
- 每个设计请求 10 个特征频率
- 模态识别会去看实际存在的解，序号可以到 20

模型文件：

- 六阶：`05_仿真与数据追加/models/plain_width6_model_manual10.mph`
- 八阶：`05_仿真与数据追加/models/plain_width8_model_manual10.mph`

两个文件各约 73 MB，git 没装下，要到 Release `models-20260929` 下载后放回 `models/`。Java 每次只改 `a_ring`、`h_ring` 和对应阶数的 `C`、`S`，然后重新生成几何、重新划分网格、运行 `std3`。模型里其余参数由 mph 自己带着，这套 Java 不改它们。

六阶 Java 是 `ScanWidth6ModesForStrictMacArgs.java`，八阶是 `ScanWidth8ModesForStrictMacArgs.java`。八阶比六阶多设 `C7,S7,C8,S8`。

每个模态导出 64 个采样点的三维位移。每个点有 `u,v,w` 三个数，所以一条位移向量是 192 个数。COMSOL 还输出该模态的频率和 `solid.Q_eig`。

## 模态怎么挑

不是频率最高或 Q 最大就留下。`simulate_and_score.py` 把这条位移和四条参考向量比。参考在 `reference/strict_mac_initial_vectors.csv`，标签是：

- `apodized_d1_m10`
- `apodized_d2_m10`
- `apodized_d3_m10`
- `width2_d1_m8`

相似度用 MAC：两条向量夹角越接近，MAC 越接近 1。每个模态对四条参考都算，取得分最高的那条。

一个模态要算「有效呼吸」，三条要同时过，阈值在 `project_config.json`：

- 最高 MAC ≥ 0.90
- 径向位移同号的比例 `same_sign_fraction` ≥ 0.95
- 呼吸均匀性 `breathing_uniformity` ≥ 0.95

配置里写明 `frequency_is_filter` 为 false：频率不拿来删模态。

同一设计的多个模态按这个顺序排序：先看有没有过三条线，再比 MAC、同号比例、均匀性。排第一的成为选中模态。过了线，`selected_Q` 才有数，`valid_for_Q` 为 1。没过线，`selected_Q` 空着，`valid_for_Q` 为 0，不进训练表。

训练 CSV 里现在每一行都是 `valid_for_Q=1`。没过线的行在导出前已经被拿掉了。

## 训练表里有什么

目录 `01_训练数据/` 有 7 个 CSV，合计 21371 行。读入后再要求 `selected_Q ≥ 1e6`，剩下 19320 行。这就是 `04_训练输出/final_mlp/training.log` 里写的两个数。Q 低于 100 万的有 2051 行，最低大约 9.3 万，最高大约 7.0×10⁷。频率大约 8.01 到 10.14 MHz。

按文件，Q ≥ 1e6 的行数是：

| 文件 | Q≥1e6 | Q<1e6 |
| --- | ---: | ---: |
| `training_q_width6_guided_coverage.csv` | 14181 | 1768 |
| `training_q_width6_symmetry_discovery.csv` | 1253 | 11 |
| `training_q_width2_strict.csv` | 1295 | 1 |
| `training_q_width6_dl_coverage.csv` | 1105 | 198 |
| `training_q_width4_strict_training.csv` | 1095 | 3 |
| `training_q_width4_dl_coverage.csv` | 213 | 26 |
| `training_q_width8_symmetry_discovery.csv` | 178 | 44 |

六阶、而且名字里带 guided 的那一个文件，占训练用行的大约四分之三。八阶通过 Q 过滤的只有 178 行。

`source_kind` 是这一行当初怎么被抽出来的标签，不是一组对照实验。行数最多的几类是 `high_h_coverage`（4900）、`large_perturb`（4159）、`surrogate_highQ`（3346）、`sparse_global`（2784）、`stratified_coverage`（1135）。带 `d4`、`d8`、`near_plain` 的是在看对称或接近光滑圆环，但半径、环宽、起伏幅度并没有在这些类之间锁死，所以不能直接说「只因为更对称，Q 就更高」。

几何四舍五入到小数点后六位后，21371 行里有 94 行和另一行重复，独立几何大约 21277 个。

每一行训练用得到的列主要是：批次、序号、半径、环宽、各阶 C/S、`source_kind`、选中的模态序号、频率、Q、同号比例、呼吸均匀性、最高 MAC、对上的参考标签、`valid_for_Q`。有的文件还有当时算出的 `width_min_um`、`width_max_um`。

## 神经网络

训练脚本是 `02_训练代码/train_final_mlp.py`。根目录的 `train.py` 和 `START_TRAINING.bat` 是入口。

网络是三层全连接：59 → 256 → 128 → 64 → 2。每一隐层后面是 ReLU、BatchNorm、Dropout（0.05）。两个输出是 `log10(Q)` 和 `selected_freq_MHz`。Q 先取对数再学，避免大 Q 把损失淹没。

损失是加权均方误差。对数 Q 的权重是 1，频率的权重是 0.7。优化器是 AdamW，学习率 8×10⁻⁴，权重衰减 1×10⁻⁴。验证损失 18 个 epoch 没有改善就把学习率乘 0.5。连续 55 个 epoch 没有刷新最好的验证损失就停。梯度范数裁到 3。最多 350 个 epoch，批大小 256。随机种子 20260626。

划分按对数 Q 的五分位和环宽的四分位分层。先留 20% 做测试，剩下的再留 18% 做验证。结果是训练 12673、验证 2783、测试 3864。缺失值用训练集的中位数填，输入和输出都按训练集做标准化。测试指标是把网络输出反标准化之后算的。

`metadata.json` 里还记了 resnet、Transformer、混合专家几种结构的配置。真正保存并被预测脚本加载的是上面这个 `torch_mlp`。

## 两份权重

仓库里有两套权重，测试集划分相同，误差不完全一样。

`03_最终模型/` 是交付时的默认模型。`predict.py` 不另写参数时就读这一套。`deep_model_summary.csv`：

- 跑了 220 个 epoch
- 对数 Q 的平均绝对误差 0.03515，R² 0.9785
- Q 的平均相对误差约 8.6%，中位数约 4.1%，90% 分位约 18.0%，95% 分位约 29.0%
- 频率平均绝对误差 0.00453 MHz，R² 0.9990，90% 分位绝对误差约 0.0094 MHz

`04_训练输出/final_mlp/` 是后来重训的。`training.log` 写明：读入 21371 行，Q 过滤后 19320 行，59 个特征，第 209 个 epoch 早停，最好的缩放验证损失 0.012038。日志里的输出目录是一台 Windows 机器上的 `D:\Codex\deeplearning\...`。这套的测试指标：

- 对数 Q 平均绝对误差 0.03728，R² 0.9768
- Q 的 90% 分位相对误差约 17.8%
- 频率平均绝对误差 0.00409 MHz

根目录 `README.md` 引用的是 7 月那套、也就是 `03_最终模型` 的误差。`find_new_designs.py` 在 `--model-dir auto` 时，只要 `04_训练输出/final_mlp/torch_mlp.pt` 存在，就用重训的这套，否则才退回 `03_最终模型`。两套不能当成同一个模型。报告里引用误差时，要写明用的是哪一个目录。

对数 Q 误差 0.035 的意思是：Q 大约差一个 10⁰·⁰³⁵ ≈ 1.08 倍的量级，和上面「平均相对误差大约百分之八」是同一件事。频率误差大约几千赫，相对 9 到 10 MHz 很小。Q 的 90% 分位仍有大约两成相对误差，所以模型适合用来挑「大概哪一片几何 Q 更高」，不适合把预测 Q 写成精确测量值。

## 四种用法

**只预测，不仿真。** 准备一个 CSV，至少有 `a_ring_um`、`h_ring_um`。缺的 `Ck_um`、`Sk_um` 会补 0。在交付包根目录运行：

```powershell
python predict.py --input example_input.csv
```

默认读 `03_最终模型`，写出 `04_训练输出/predictions.csv`，列是 `pred_log10_Q`、`pred_Q`、`pred_freq_MHz`。`example_input.csv` 里有一行例子：半径约 129.12 μm，环宽约 9.69 μm，主要起伏在第 4 阶。这台机器装上 `requirements.txt` 里的 Python 包之后可以做这件事，不需要 COMSOL。

**用现成表重新训练。** 根目录 `python train.py`，或 Windows 上双击 `START_TRAINING.bat`。新权重写到 `04_训练输出/final_mlp/`，会盖住那份重训结果。种子相同，换机器、换线程数，误差仍可能和上面两套差一点点。README 写了这一点。

**只生成下一批待仿真的几何，不跑 COMSOL。** `generate_new_designs.py` 或 `GENERATE_NEW_DESIGNS.bat`。配置在 `design_search_config.json`：默认 6 阶、提出 6 个点、候选池 12000、大约 67% 的名额用来铺开还没覆盖的区域、其余偏向预测 Q 高的点、预测 Q 低于 1e6 的丢掉、种子 20260929。新点和已有点的距离用几何坐标的尺度归一化之后算，默认至少隔开 0.04。以前提出过的点记在 `04_训练输出/candidate_search/`，下一轮会躲开。6 阶搜索会先丢掉第 7、8 阶系数不为 0 的旧行，避免拿八阶几何来量六阶距离。

默认输出是 `05_仿真与数据追加/input/designs_width6_auto.csv`。6 个点里大约 4 个标成 `coverage`，2 个标成 `surrogate_highQ`。

**真的跑新仿真并追加。** 必须在装了 COMSOL 6.3 和对应许可证的 Windows 上，并且 mph 已经放回 `models/`。`python python/simulate_and_score.py --order 6 --input <设计.csv> --label <批次名> --append`。脚本会跑 COMSOL、解析位移、打模态分数，把通过的行追加到 `01_训练数据/training_q_user_added.csv`。输出在 `05_仿真与数据追加/output/<批次名>/`：`mode_scores.csv`、`summary.csv`、`training_valid.csv`，以及原始日志 `comsol_raw.log`。追加之后要再跑训练，新行才会进权重。

`AUTO_FIND_AND_RUN.bat` 把「找点、仿真、追加、重训」串成一次。`RUN_GENERATED_DATA.bat` 只跑已经生成并且人看过的那份 auto CSV，不会另找一批点。

## 和论文里那枚圆环不是同一颗

学位论文里的电容耦合呼吸圆环，内半径 60 μm，外半径 68 μm，环宽固定 8 μm，硅厚 20 μm，仿真频率大约 19.3 MHz。学长这套扫的是平均半径大约 125 μm、环宽大约 8 到 13.5 μm、频率大约 8 到 10 MHz，而且环宽沿圆周在变。两边都是呼吸模态这一族，半径大约差一倍，频率大约差一倍。不能把论文里的拐点、ppb、加热功率填进这套模型，也不能把这套模型的 Q 说成论文那颗器件的 Q。

## 引用边界

可以写进材料、但必须标明是学长已有工作的：

- 19320 条 Q≥1e6 的仿真，以及 21371 条已经通过模态筛选的表
- 上面两套 MLP 的测试误差，并写明是 `03_最终模型` 还是 `04_训练输出/final_mlp`
- 模态筛选的三条阈值，和「频率不参与筛选」
- 预测脚本和找点脚本的用法

不能写成你们这次成果的：

- 这些 Q 和频率。它们是他的 COMSOL 结果，不是你们今年测的，也不是你们今年新跑的
- 把模型预测的 Q 说成实验品质因数
- 用这张表证明频率随温度更稳，或加热更省。表里没有温度扫描
- 把 `source_kind` 的高低 Q 直接说成「只改了对称性」的结论。那些类里半径、环宽和起伏幅度也在变

重跑一遍一模一样的 19320 条，得到的仍是他的流程和他的模型设定。误差也不会和上面两套权重逐位相同，因为 7 月交付和 9 月重训已经不同。
